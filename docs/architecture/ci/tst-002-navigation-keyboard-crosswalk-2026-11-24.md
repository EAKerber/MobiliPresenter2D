## Event, cost and friction disposition

- Development and main-bound public navigation use the same 124-case source but not the same event scope: local static execution is for PR/push on development; the second run is for non-draft PRs to main. They do not run twice for one ordinary PR.
- The Viewer 20-case gate is a different shell contract from the public 124 cases.
- The Flow Layout 32-case test runs in the full Flow Layout PR gate. The development boundary workflow runs it after a push to development when its isolated test/workflow paths change. These are pre-merge and post-merge event scopes, not duplicate execution for one event.
- The hosted public smoke is intentionally main-preview-only. Its PR path also matches development, where static contracts run and the live-preview job is skipped. The candidate now runs node --check on that smoke source in the static job, so an edit is syntax-checked on development without creating a second deployed browser preview. Behavioral hosted evidence remains required on a main-bound PR that carries the smoke/source change.
- Keyboard Browser and Flow Layout previously installed Playwright browser binaries on each hosted run. The candidate swaps only their setup to the same pinned Playwright 1.62.1 Noble image already used by other project gates and keeps Playwright 1.62.1 as the Node package. Chromium/WebKit assertions, local V5 fixture, event filters and optional manual target remain unchanged. This removes the repeated browser-binary install step; no duration saving is claimed until candidate runs are measured.
- No test assertions are removed or weakened. The current PR is expected to run Keyboard Browser, Flow Layout, and the public routing static job on the exact candidate head; those runs will validate the setup change.

Their apparent overlap in theme mode is not duplicate assertion coverage.
