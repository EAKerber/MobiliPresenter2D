### Other state controls in the Admin shell

These are not product-configuration booleans and should not share semantics or keys with the checkboxes above:

- Password reveal has two instances (`admin.html:43,54`): pressed means plaintext; unpressed means masked. `syncPasswordReveal` updates `aria-pressed`, accessible name/title (“Mostrar/Ocultar senha”), and button text (`admin.js:100–112`; sink `064500918d629241`). Presentation only.
- Private menu is a disclosure: `hidden` and `aria-expanded` remain synchronized with “Abrir/Fechar menu” (`admin.html:21–22`; `app/core/private-navigation.js:106–112`).
- Admin tabs are selected/unselected navigation (`admin.html:73–85`; `admin.js:1302–1311,1340–1344`), not saved configuration. Source sets `aria-selected` and hides panels on click; keyboard/runtime relationship was not validated.
- Material pickers use native `<details>/<summary>` disclosure; their `open` state can be initialized from `optionsOpenByDefault` (`admin.js:376`) and does not itself mutate the product model.
- Shared theme button is **tri-state**, not binary (`auto/light/dark`); its accessible name describes current/next mode and preference persists as presentation state (`app/core/ui-theme.js:5–10,30–38,60–84`; shared-runtime sink `126e4062316603da`). In auto mode the OS preference resolves the palette, so native checkbox accent cannot be treated as an intentional hierarchy token.
