# CP-PUBLIC-05 — inventário de duplicações, artefatos e higienização

Data: 2026-10-08. **Inventário / sem exclusão de código neste checkpoint.** Evidência: `main` em `bf30e008a81b7bc9cc34573e3d60a953810a9e72` e árvore staging da [PR #180](https://github.com/EAKerber/MobiliPresenter2D/pull/180) em `82d85674595280a7c878848d0d5f09df29492e92`. `main` ainda **não** contém as páginas públicas nem o novo `scene-component`.

## Contrato de produto (impede refatoração errada)

O **Viewer apresenta módulos**, com cena, vistas, título/destaques/componentes/requisitos, navegação e eventual escolha global de cor das **frentes**. Ele **não** edita a composição comercial, nem seleciona os serviços de pedra e rodapé, nem aplica as regras de oclusão/visibilidade condicional de compra do configurador. **A cena mostrada atualmente no preview é o baseline visual aceito para esse fim**, sujeita apenas a correções de regressão/usabilidade reais; paridade com o runtime da pedra/rodapé/oclusão do configurador deixou de ser gate por decisão explícita. Caixaria/laterais visualmente congeladas por prazo indeterminado. Seletor de cor das frentes: **opcional**, não condição de publicação; o adapter já possui `getState/subscribeState/setGlobalFinish/getFinishes`.

Logo, **não mover indiscriminadamente `app/app.js` para o viewer**. Antes de abstrair, provar que cada função compartilhada preserva semântica e output dos *consumidores próprios*. Diferença entre compra e vitrine não é duplicação removível por si.

## Ordem recomendada de higienização (não executar antes dos gates)

1. **Segurança CP-PUBLIC-03:** bloquear superfície privada, decidir preço estático e homologar sessões.
2. **Remoção da infraestrutura provisória #180:** fixture/plugin/diagnóstico/testes acoplados ao ID — limpeza obrigatória e pequena.
3. **Deduplicação de algoritmo SVG** em commit independente e gates dos dois consumidores. Sem redesenho de pedra/rodapé no viewer.
4. **Partilha seletiva de helpers** de URL, bounds, hotspots e tokens, somente após inventariar dependências reais.
5. **Limpeza do bundle, CSS, assets e docs obsoletas** por relatório de usos (HTML `<script>`, imports, runtime global, tests, URLs), com dry-run / backup/rollback. Nunca inferir arquivo morto apenas por não aparecer em import ESM: o projeto usa globals e script tags.

## Protocolo de remoção

Cada artefato precisa registrar: `path`, `consumidores`, `autoridade`, `substituto`, `teste de ausência`, `rollback`. Remover em lote pequeno; rodar `npm test`, Playwright landing/viewer, CI mobile, auditoria visual e busca global por referências; reprovar se houver asset 404, quebra de estilos, módulo perdido, regressão de teclado ou discrepância editorial.

**Invariantes:** não tocar a publicação v5, não alterar a UI de comprador aceita por “reaproveitamento”, não retroceder para catálogo doador, não implementar máscara/caixaria ou oclusão comercial no viewer, não apagar fixtures até o teste de isolamento/publicação estar substituído.
